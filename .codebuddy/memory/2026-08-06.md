## WeCom 推送与 Reports 页结构对齐（commit 39799c0，已 push + 部署）
- 背景：用户发现企微推送内容与 Reports 页不一致。根因——两者读同一份 `structured_content`，但用两个独立渲染函数：前端 `DigestCard`（reports/index.vue）随事件化重构升级为 核心变化/必须知道/值得留意/持续关注/接下来关注；而后端 `build_wecom_digest_summary`（digest_service.py:462）停留在旧 schema，只渲染 period_summary + must_know + worth_watching + upcoming。
- 差异点：① 推送用 `period_summary`(prose) 而页面用 `cross_event_signals`(核心变化) → 内容完全不同；② 推送**完全缺失** `持续关注`(ongoing_updates+quiet_topics)，页面有；③ worth_watching 推送封顶 5 条、页面全量。
- 修复（方案A，用户选定）：推送函数改为用 `cross_event_signals` 渲染「💡 核心变化」（替换旧「📌 本时段概况」），并新增「👁 持续关注」合并 `ongoing_updates`+`quiet_topics`（每条 title + note）。保留 必须知道/值得留意(≤5)/接下来关注(≤3) 与原文链接。
- 验证：`py_compile` 通过；Lighthouse `git pull`(51d1c8a→39799c0) + `docker compose up -d --build web` 成功，/api/v1/health 返回 200。
- 生效：下次定时简报推送起按新格式；手动验证可跑 `scripts/push_latest_digest.py`。
- 教训：同一份结构化数据被前端卡片和后端推送两路独立渲染，schema 演进时易脱节。后续若再扩 digest section，需同步改 `DigestCard` 与 `build_wecom_digest_summary`（以及 `_render_markdown` 旧 Markdown 兼容函数）。
