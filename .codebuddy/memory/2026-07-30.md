### 高危清单（均已附 file:line 证据）
1. **新闻静默丢失链（P0）**：①dedup 索引在成功前 save_index → 失败条目下轮被自索引当重复丢弃（deduplicator.py:251-254,368-373）；②content_risk 二分中 api_error 子批合并为 ok 被误标 seen（llm_news_filter.py:947-966）；③missing_ids(LLM 漏评≤20%) 重试后照收被当低分标记 seen（llm_news_filter.py:833-853）。根因：标记 seen 只看 batch 级 had_errors，不看条目级是否真被评分/存储。
2. **调度器锁状态机缺陷（P0）**：续期一次失败(含 Redis 瞬时抖动)即永久停调度且无看门狗自愈(scheduler.py:118-148)；fail-open 场景两 worker 全启动后首次续期发现 key 不存在双双自杀。7/16 自愈只覆盖"启动未获锁"路径。
3. **迁移不完整（P1）**：5 张核心表(stock_daily_quote/stock_rs_rating/analytics_daily/pipeline_runs/news_catalyst_stocks)无 create_table 迁移(靠 dev create_all 隐式建)；news.related_to_id 模型有列无迁移；模型与迁移字段漂移(sandbox String 200 vs 500)。
4. **安全（P1）**：VITE_API_KEY 编译进公开 H5 bundle→鉴权≈0；全站零限流且 /digests/generate、/briefings/generate、/quotes/backfill、/pipeline/run 可被刷 DeepSeek 账单；sandbox/SEPA"私密"仅前端 UX 锁、GET 端点不验密码；空密钥静默放行无 fail-fast。
