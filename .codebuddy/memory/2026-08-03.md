### 21. P0 Bug：同一事件跨栏目重复导致 digest_event_links 唯一约束事务失败（commit 7bf8f3a，已提交未部署）
- **现象**：LLM 可把同一 `event_id` 同时放入 `must_know` / `worth_watching`（甚至 `ongoing_updates`）。`_parse_briefing_json` 不跨栏去重，`_save_event_links` 对每栏逐条建 `DigestEventLink`，而 `digest_event_links` 有 `(digest_id, event_id)` 唯一约束 → 偶尔重复分配就会让整条写入事务失败，简报任务 P0 级失败。
- **修复**（backend/app/services/digest_service.py）：
  1. 新增 `_dedupe_structured(structured, events)`：优先级 `must_know > worth_watching > ongoing_updates`，栏内重复与跨栏重复均丢弃低优先级副本；`cross_event_signals.event_ids` 仅引用不写独立 link 不去重；LLM 返回空 `title` 时用事件库正式标题（`r.event_title or r.title`）回填。
  2. LLM 路径解析成功后调用；no-LLM 分支（此前修复的无事件 v2 简报）也调用，保持一致/兜底。
  3. `_save_event_links` 写入前增加防御性去重（按 `(digest_id, event_id)` 去重），即便上游漏去重也绝不触发唯一约束失败（最后一道防线）。
- **实测**：①纯函数单测 6 条断言通过（跨栏/栏内去重、空标题回填、cross 引用保留、三栏并集唯一）；②容器内用真实事件根 ID mock LLM 返回跨栏重复，`generate_digest` 返回 `status=ok`，`digest_event_links` 总条数=唯一数=2、must_know 仅 A/B（worth_watching 副本被丢弃），无重复行、事务不失败。测试数据已清理。
- **部署**：已 `git push`（7bf8f3a），但用户拒绝了自动部署命令，**尚未部署到线上**。需用户确认后再 `git pull && docker compose up -d --build web`。
- 教训：凡 LLM 可被要求输出事件列表的多栏目结构，落库前必须在应用层做跨栏去重 + 防御性去重，不能依赖 LLM 自律。
